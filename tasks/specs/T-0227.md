# T-0227: Spec Dossier Integrity Checker

## 1. Overview & Curative Mission Focus (Scientific Integrity / Quality)
To prevent context loss, hallucinated endpoints, or ambiguous tasks across multi-turn autonomous agent loops, every new complex task on `tasks/board.json` is anchored by a rich specification dossier under `tasks/specs/<TASK-ID>.md`. Each dossier provides full biophysical equations, primary literature citations (DOI, NCT, PDB), exact file paths, DOM element IDs, and deterministic test commands.

This specification directs the implementation of an automated spec dossier integrity checker in `cf-lab` (`tasks/check_task_specs.py` and `tasks/test_check_task_specs.py`) ensuring that every declared `spec_path` in `board.json` resolves to a valid, structurally complete dossier.

## 2. Primary Evidence Grounding
- **Task Board Data Store**: `tasks/board.json` containing task definitions, priorities, ROI estimates, and declared `spec_path` fields.
- **Triage & Anti-Hallucination Guardrails**: `tasks/triage_board.py` enforcing primary literature anchors (DOI, NCT, PDB) and non-empty acceptance criteria.
- **Board Renderer**: `tasks/render-board.ps1` formatting `spec_path` links into `tasks/BOARD.md`.

## 3. Architecture & Functional Requirements
- **Verification Criteria**:
  1. File Existence: Every task with `"spec_path": "tasks/specs/T-XXXX.md"` in `tasks/board.json` must resolve to an existing markdown file.
  2. Heading & Length: The markdown file must begin with a level-1 markdown heading (`# T-XXXX ...`) and contain at least 100 characters.
  3. Primary Literature Grounding: The text must cite at least one verifiable identifier:
     - Digital Object Identifier: `10.XXXX/...`
     - ClinicalTrials.gov Protocol: `NCTXXXXXXXX`
     - Protein Data Bank Coordinate ID: `6MSM`, `8EIQ`, `5UAK`, or explicit `PDB: XXXX`
     - PubMed ID: `PMID: XXXXXXXX`
     - Catalog Dataset: `catalog.yaml` or `sources/`
  4. Verifiable Execution: The document must include at least one concrete CLI test command (`python`, `pytest`, `pwsh`, `unittest`).
  5. Bidirectional Consistency: Every markdown file present in `tasks/specs/T-XXXX.md` must correspond to a valid task on `tasks/board.json` with a matching `spec_path`.

## 4. Deliverables & Target Files
- In repository `cf-lab`:
  - `tasks/check_task_specs.py`: Verification utility with `--check`, `--board`, `--specs-dir`, and `--json` support.
  - `tasks/test_check_task_specs.py`: Full unit test suite testing valid dossiers, missing files, missing citations, missing commands, and CLI invocations.
  - `tasks/triage_board.py`: Integrated `verify_task_spec` into `is_grounded_executable`.

## 5. Verification Command
Deterministic execution verifying zero external network calls:
```bash
python -m unittest tasks/test_check_task_specs.py
```
Or via script check:
```bash
python tasks/check_task_specs.py --check
```
